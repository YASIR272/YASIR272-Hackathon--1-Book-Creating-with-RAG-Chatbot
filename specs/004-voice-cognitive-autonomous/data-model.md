# Data Model: Module 4 – Voice-to-Action & Cognitive Planning (LLMs & Autonomous Humanoids)

**Date**: 2025-12-17
**Feature**: 004-voice-cognitive-autonomous
**Status**: Complete

## Overview

This document defines the data structures and relationships for Module 4 of the ROS 2 for AI Developers book. The module covers Voice-to-Action systems, Cognitive Planning with Large Language Models (LLMs), and Autonomous Humanoid capstone projects, requiring a comprehensive data model to support the VLA (Vision-Language-Action) integration.

## Core Entities

### VoiceCommand
**Description**: Represents a voice command received by the system
- `id`: UUID - Unique identifier for the command
- `transcript`: String - Text transcription of the spoken command
- `confidence`: Float - Confidence score of speech recognition (0.0-1.0)
- `timestamp`: DateTime - When the command was received
- `intent`: String - Parsed intent from the command
- `parameters`: Dictionary - Extracted parameters from the command
- `processed_by`: String - ID of the processing agent
- `status`: Enum ['received', 'processing', 'executing', 'completed', 'failed']

### CognitivePlan
**Description**: Represents a high-level plan generated by LLM-based cognitive reasoning
- `id`: UUID - Unique identifier for the plan
- `name`: String - Descriptive name for the plan
- `description`: String - Detailed description of the plan
- `tasks`: Array[Task] - List of tasks in the plan
- `dependencies`: Array[Dependency] - Task dependencies
- `created_by`: String - ID of the LLM that generated the plan
- `created_at`: DateTime - Timestamp of plan creation
- `estimated_duration`: Integer - Estimated time to complete (seconds)
- `status`: Enum ['draft', 'approved', 'executing', 'completed', 'aborted']

### Task
**Description**: Individual task within a cognitive plan
- `id`: UUID - Unique identifier for the task
- `name`: String - Short name for the task
- `description`: String - Detailed description of the task
- `type`: Enum ['navigation', 'manipulation', 'communication', 'perception', 'other']
- `parameters`: Dictionary - Parameters for task execution
- `priority`: Integer - Priority level (1-10)
- `estimated_duration`: Integer - Estimated time to complete (seconds)
- `preconditions`: Array[String] - Conditions that must be met before execution
- `postconditions`: Array[String] - Expected state after completion
- `status`: Enum ['pending', 'ready', 'executing', 'completed', 'failed']

### Dependency
**Description**: Relationship between tasks indicating execution order
- `id`: UUID - Unique identifier for the dependency
- `source_task_id`: UUID - ID of the task that must complete first
- `target_task_id`: UUID - ID of the task that depends on the source
- `type`: Enum ['finish_to_start', 'start_to_start', 'finish_to_finish', 'start_to_finish']

### ActionSequence
**Description**: Low-level sequence of robot actions derived from cognitive plan
- `id`: UUID - Unique identifier for the action sequence
- `plan_id`: UUID - Reference to the parent cognitive plan
- `actions`: Array[RobotAction] - Ordered list of robot actions
- `execution_order`: Integer - Order in which this sequence executes
- `estimated_duration`: Integer - Estimated time to complete (seconds)
- `status`: Enum ['pending', 'ready', 'executing', 'completed', 'failed']

### RobotAction
**Description**: Specific action to be executed by the robot
- `id`: UUID - Unique identifier for the action
- `name`: String - Name of the action (e.g., "move_forward", "grasp_object")
- `type`: Enum ['navigation', 'manipulation', 'perception', 'communication', 'wait']
- `parameters`: Dictionary - Action-specific parameters
- `duration`: Integer - Expected duration of the action (seconds)
- `priority`: Integer - Priority level (1-10)
- `status`: Enum ['pending', 'executing', 'completed', 'failed', 'interrupted']

### PerceptionResult
**Description**: Result from perception/vision processing
- `id`: UUID - Unique identifier for the result
- `timestamp`: DateTime - When the perception occurred
- `sensor_data`: Dictionary - Raw sensor data used for perception
- `detected_objects`: Array[DetectedObject] - Objects detected in the environment
- `environment_state`: Dictionary - Current state of the environment
- `confidence`: Float - Overall confidence in the perception (0.0-1.0)
- `context`: String - Context in which the perception occurred

### DetectedObject
**Description**: Individual object detected by the vision system
- `id`: UUID - Unique identifier for the detected object
- `name`: String - Name or classification of the object
- `type`: String - Type of object (e.g., "chair", "table", "person")
- `position`: Position3D - 3D position of the object
- `orientation`: Quaternion - Orientation of the object
- `dimensions`: Dimensions3D - Size of the object
- `confidence`: Float - Confidence in the detection (0.0-1.0)
- `properties`: Dictionary - Additional properties of the object

### Position3D
**Description**: 3D position in space
- `x`: Float - X coordinate
- `y`: Float - Y coordinate
- `z`: Float - Z coordinate

### Quaternion
**Description**: Rotation in 3D space using quaternion representation
- `x`: Float - X component
- `y`: Float - Y component
- `z`: Float - Z component
- `w`: Float - W component

### Dimensions3D
**Description**: 3D dimensions of an object
- `width`: Float - Width of the object
- `height`: Float - Height of the object
- `depth`: Float - Depth of the object

### ConversationHistory
**Description**: History of interactions between user and system
- `id`: UUID - Unique identifier for the conversation
- `user_id`: String - Identifier for the user
- `messages`: Array[ConversationMessage] - Ordered list of messages
- `created_at`: DateTime - When the conversation started
- `last_updated`: DateTime - When the conversation was last updated
- `context`: Dictionary - Current context for the conversation

### ConversationMessage
**Description**: Individual message in a conversation
- `id`: UUID - Unique identifier for the message
- `sender`: Enum ['user', 'system'] - Who sent the message
- `content`: String - Content of the message
- `timestamp`: DateTime - When the message was sent
- `intent`: String - Intent parsed from the message
- `action_taken`: String - Action taken as a result of the message

## Relationships

### VoiceCommand → CognitivePlan
- One VoiceCommand can generate one CognitivePlan
- Relationship: 1:1 (each voice command triggers one plan)

### CognitivePlan → Task
- One CognitivePlan contains many Tasks
- Relationship: 1:N (one-to-many)

### Task → Dependency
- One Task can have many Dependencies (as source or target)
- Relationship: 1:N (one-to-many)

### CognitivePlan → ActionSequence
- One CognitivePlan contains many ActionSequences
- Relationship: 1:N (one-to-many)

### ActionSequence → RobotAction
- One ActionSequence contains many RobotActions
- Relationship: 1:N (one-to-many)

### PerceptionResult → DetectedObject
- One PerceptionResult contains many DetectedObjects
- Relationship: 1:N (one-to-many)

### ConversationHistory → ConversationMessage
- One ConversationHistory contains many ConversationMessages
- Relationship: 1:N (one-to-many)

## Validation Rules

### VoiceCommand
- `transcript` must not be empty
- `confidence` must be between 0.0 and 1.0
- `timestamp` must be in the past or present
- `status` must be one of the allowed enum values

### CognitivePlan
- `tasks` array must not be empty
- `created_at` must be in the past or present
- `estimated_duration` must be positive
- `status` must be one of the allowed enum values

### Task
- `priority` must be between 1 and 10
- `estimated_duration` must be non-negative
- `status` must be one of the allowed enum values

### RobotAction
- `priority` must be between 1 and 10
- `duration` must be non-negative
- `status` must be one of the allowed enum values

### PerceptionResult
- `confidence` must be between 0.0 and 1.0
- `timestamp` must be in the past or present

### DetectedObject
- `confidence` must be between 0.0 and 1.0
- `dimensions` values must be positive

## State Transitions

### VoiceCommand Status Transitions
```
received → processing → executing → completed/failed
```

### CognitivePlan Status Transitions
```
draft → approved → executing → completed/aborted
```

### Task Status Transitions
```
pending → ready → executing → completed/failed
```

### RobotAction Status Transitions
```
pending → executing → completed/failed/interrupted
```

### ActionSequence Status Transitions
```
pending → ready → executing → completed/failed
```
